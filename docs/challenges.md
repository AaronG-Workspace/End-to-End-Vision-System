# Challenges

Corrections from Tom during the build: what Claude proposed, what Tom caught, what changed.

- 2026-10-25, data.py: Claude proposed checking only the per-folder image counts. Tom caught that the data came from a third-party mirror, so matching counts do not prove these are the original files. data.py now asserts every image is 900x900 before hashing it.
- 2026-10-25, calibrate.py: Claude made F1-optimal the primary threshold, as CLAUDE.md specified. Tom caught that val was perfectly separated, so the F1-optimal value (gap midpoint, FP32 1.629) was set by synthetic defects now known to be unrealistic, and that in medical-device QC a missed defect costs more than a false reject. The primary is now max_val_normal for both variants (FP32 1.279, INT8 1.334), with F1-optimal reported as the alternative.
- 2026-10-26, eval.py: Claude set sanity check 4 as random-sign mean score shift < 0.25 x FGSM shift. The val dry run failed it narrowly at eps 0.02 (0.1734 vs a 0.1715 limit) because FGSM stops getting stronger and random noise raises every score. Claude proposed judging check 4 on the drop in AUROC instead, and Tom set the rule: random-sign AUROC drop <= 0.25 x FGSM drop, or <= 0.01. The cutoff was revised after the val dry run, before freeze, and score shifts are still printed. Tom also approved Claude's proposal to report escape and false-alarm AUROC halves separately.
- 2026-10-26, leakage_audit.md: Claude marked row 9 (files that open test images) as PASS with a pointer to known issue 2. Claude had disclosed that report.ipynb's guard self-test opened a test file handle twice after the run, and offered to mark the row FAIL-then-fixed instead. Tom decided the row reads "PASS before the test run", with the post-run incident stated in the row itself: one handle opened twice, no bytes read, no number affected, fixed.
